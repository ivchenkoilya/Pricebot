# Changelog

## Clarify 0.6.0 — MINI APP

Главная цель релиза — превратить Telegram-бота Clarify в цельный коммерческий продукт с полноценным Mini App, не создавая второй backend или отдельную базу.

### Новый `/start`

- фирменный баннер хранится в `assets/clarify_banner.webp`;
- короткое позиционирование «Перешли то, на что не хочется тратить время»;
- WebApp-кнопка `🚀 Открыть Clarify` при настроенном `WEBAPP_URL`;
- быстрые кнопки материалов, PRO и помощи;
- owner видит `OWNER · Unlimited`.

### Mini App

Добавлен React/Vite/TypeScript frontend с mobile-first интерфейсом:

- Home;
- Materials + search/filters;
- Material Details + AI Q&A/actions/sources;
- Projects + project Q&A;
- Compare;
- Reminders;
- Write for me;
- PRO + Telegram Stars;
- Profile/Settings;
- OWNER state.

Frontend собирается внутри production Docker и раздаётся тем же FastAPI по `/app/`.

### Telegram security

Mini App API не доверяет client-supplied `user_id`. Backend валидирует Telegram `initData` через HMAC-SHA256 с `BOT_TOKEN`, проверяет `auth_date`, извлекает подписанный user payload и после этого ограничивает все материалы/проекты/напоминания текущим пользователем.

### Backend API

Добавлены same-origin `/api/*` endpoints для профиля, материалов, Q&A/actions, проектов, сравнения, напоминаний, compose/rewrite, PRO invoice, settings и privacy delete. AI-функции используют существующие provider/retrieval/quota/services — второго AI pipeline нет.

### Production

- Docker multi-stage Node 22 → Python 3.12;
- GitHub Actions проверяет Python compile, pytest, TypeScript, Vite build и Docker build;
- та же `/data/price.db`;
- та же Amvera persistence `/data`;
- `WEBAPP_URL` и auth/CORS настройки вынесены в env;
- миграция базы не требуется.

## Clarify 0.5.0 — COPILOT

Главная цель релиза — превратить Clarify из обработчика отдельных файлов в помощника, который понимает продолжение разговора и сразу отвечает на задачу пользователя.

### Ссылки

Теперь URL обрабатывается как веб-страница, а не как обычный текст.

Примеры:

- отправить только ссылку → Clarify читает страницу и делает разбор;
- `https://example.com ... что здесь главное?` → отвечает именно на вопрос по странице;
- страница сохраняется как материал, поэтому по ней можно продолжать диалог и использовать обычные действия.

Для чтения переиспользуется безопасный `PageReader`: обычный HTML → Jina Reader fallback → публичный URL fallback. CAPTCHA, login и access-control не обходятся.

### Мультимодальные подписи

Подпись к фото или документу теперь считается задачей пользователя.

Примеры:

- фото + `что у него на голове?`;
- PDF + `когда нужно оплатить?`;
- скриншот + `что здесь не так?`.

Clarify отвечает сразу на подпись, а не сначала выдаёт стандартный полный разбор.

### Контекст нескольких материалов

Диалог больше не привязан жёстко только к самому последнему материалу. Clarify выбирает маленький рабочий набор из недавних материалов по:

- смысловым словам запроса;
- времени;
- ссылкам `этот`, `предыдущий`, `второй`, `там` и т. п.

Например после фото, договора и голосового можно спросить `а что там было про гарантию?` — бот должен вернуться к договору, а не к последнему фото.

### Источники и страницы

Для PDF сохраняются маркеры `[Страница N]`. Q&A теперь явно инструктирует модель указывать страницу для ключевых фактов, если этот номер присутствует в retrieved-контексте. При ответе по нескольким материалам модель также получает названия источников.

### Более короткий интерфейс

Для фото и голосовых добавлена compact-карточка: прямой вывод идёт первым, а подробности показываются только если полезны. Убрана необходимость каждый раз начинать ответ с большого блока `Коротко / Главное / ...`.

### Неуверенность вместо догадки

Vision-инструкции теперь требуют явно говорить, если визуальную деталь нельзя уверенно определить, вместо уверенной догадки.

### Совместимость

- `/data/price.db` не меняется;
- новых обязательных env-переменных нет;
- миграции не требуются;
- PRO/Stars, проекты, материалы и legacy Pricebot сохраняются.

## Clarify 0.4.0 — CONTEXT

Главная цель релиза — сделать Clarify диалоговым помощником, а не набором независимых обработчиков.

### Контекстные уточнения

Короткие вопросы после недавно разобранного материала теперь относятся к нему, даже если пользователь не ставит знак вопроса.

Примеры:

- `В какой маске этот человек`
- `на каком фоне это снято`
- `какого цвета у него одежда`
- `что у него в руках`
- `где этот человек находится`
- `в каком месте они стоят`
- `у кого это было`
- `что за предмет`

Поддержаны естественные конструкции `в какой`, `в каком`, `на какой`, `на каком`, `какого`, `какую`, `у кого`, `из чего`, `с чем`, `про что`, `о чём` и другие.

### Повторный просмотр исходного изображения

Если уточнение явно относится к визуальной детали, Clarify теперь не ограничивается старой текстовой выжимкой. Бот повторно скачивает сохранённый Telegram `file_id` исходного изображения и задаёт vision-модели именно вопрос пользователя.

Например после фото:

`В какой маске этот человек`

Clarify повторно смотрит оригинальное изображение и отвечает по нему, даже если тип маски не попал в первоначальную краткую выжимку.

Если повторный vision-запрос временно недоступен, обработка мягко откатывается к обычному Q&A по сохранённому материалу.

### Восстановление после старого бага

Если предыдущая версия уже успела сохранить короткий визуальный вопрос как отдельный текстовый материал, 0.4 умеет распознать такую запись и использовать непосредственно предшествующее изображение вместо неё.

### Защита от неправильного контекста

Clarify не должен автоматически привязывать любой новый короткий запрос к прошлому материалу. Например, после фотографии фраза `как сделать сайт для магазина` остаётся новым самостоятельным запросом.

### Что исправлено

Раньше фраза `В какой маске этот человек` могла пройти как новый текстовый материал и создать бессмысленную запись `Материал добавлен`. Теперь при наличии свежего материала она классифицируется как `question`, использует нужный контекст и не создаёт новый материал.

### Совместимость

- база `/data/price.db` не меняется;
- миграций нет;
- PRO/Stars не затронуты;
- Pricebot legacy-модули не затронуты;
- текущие проекты, материалы и пользовательские стили сохраняются.
